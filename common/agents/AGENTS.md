# AGENTS.md
## 基本原則
- 文件、程式碼註解與 Git commit 使用繁體中文，禁止使用中國大陸慣用語
- 修改前先理解需求、相關程式碼與專案規範；不確定且會影響實作方向時，先釐清再修改。
- 在滿足需求的前提下，優先選擇正確、清楚、穩健且可維護的方案。
- 遵守 YAGNI，不為未被驗證的未來需求增加不必要的抽象、架構或擴充性。
## 修改原則
- 保持修改範圍聚焦，不任意修改或重構與任務無關的程式碼。
- 優先解決問題根因，避免只處理表面症狀或加入不必要的 workaround。
- 發現範圍外問題時，除非與當前任務直接相關且風險極低，否則只提醒，不主動修改。
- 修復 Bug 時，優先嘗試重現問題；無法確認根因時，明確區分已知事實與推論。
## 驗證原則
- 修改後依變更內容與風險進行驗證，確認行為符合預期且未造成回歸。
- 不得忽略、隱藏或規避驗證過程中發現的問題。
- 無法充分驗證時，如實說明驗證範圍、限制與剩餘風險。
